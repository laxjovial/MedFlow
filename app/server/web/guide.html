How to use MedFlow

From first account to daily workflow — the way clinics actually run it.

Getting started

Create the account

Sign up with a password or Google on this site. The very first account in a fresh installation becomes the administrator.

Sign in

The same credentials work on the web workspace and the desktop app. Sessions last 12 hours; sign in again when they lapse.

Register your first patient

Patients → “New patient”. Only the name is required; add age, contacts, and a working diagnosis as you go.

Chart the visit

Open the record and use the inline row in each section — vitals, diagnoses, medications, allergies, labs, notes. Everything lands on the timeline.

Run the schedule

Appointments → “Schedule”, then advance statuses as the visit progresses: scheduled → checked in → in progress → completed.

Back up before you sleep

Settings → “Create backup now”, or let an automation rule do it. Snapshots are plain SQLite files you can copy anywhere.

Sharing access safely

Need an external consultant or a supervisor to review one patient? In the web workspace open Access in the sidebar, pick the patient(s), set how long the window stays open, and hand over the generated username and password. They see exactly those records and nothing else, and the account stops working the moment it expires — or instantly, if you revoke it.

Running the desktop app

Install the MedFlow desktop program the way your computer person sets up any program — download it, open it, sign in. Your sign-in works exactly the same as on this website: the moment you're in, every record, department and report is right there, with or without internet. If your facility runs several computers, each one signs in to the same database, so everyone always sees the same up-to-date records.

For the technically curious (optional)

Everything below is for developers — you never need any of it to use MedFlow.

Developer setup & commands
python -m venv .venv # Windows: .venv\Scripts\activate — macOS/Linux: source .venv/bin/activate pip install -r requirements.txt python main.py # desktop app python main.py --server # web workspace + API on your own machine

The site you're reading, the workspace, and the API (/docs) all come from that one process. A packaged installer is planned so even this disappears.
